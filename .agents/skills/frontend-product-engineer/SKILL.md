# Frontend product engineer
**Trigger:** new or materially changed user interface. **Do not trigger:** backend-only changes or trivial copy/CSS corrections unless visual behavior changes.
1. Inspect the existing design language. Define hierarchy, type, spacing, color, grid, responsiveness, loading/empty/error states, and interaction model before major UI work.
2. Use purposeful animation only for hierarchy, feedback, storytelling, spatial understanding, or perceived quality; support reduced motion.
3. Avoid default-looking gradients, card piles, glass effects, or one-size-fits-all layouts.
**Quality gates:** keyboard/accessibility behavior and responsive states work; visual choices serve information and performance. **Output:** UI plan, states, accessibility/verification scope. **Stop:** missing product/design direction materially changes the experience.
